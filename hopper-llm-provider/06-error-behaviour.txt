Key validation behaviour at the fixed Hopper endpoint (live, 2026-10-01, fake key everywhere):

wrong Hopper key, Hopper provider
  -> rejected: Invalid Hopper API key. The key was rejected by the API at https://api.withhopper.com/v1. Please check that your API key is correct and has not been revoked.
Hopper key pasted into the OpenAI provider
  -> rejected: Invalid OpenAI API key. The key was rejected by the OpenAI API. Please check that your API key is correct and has not been revoked. You can verify your keys at https://platform.openai.com/api-keys.
Hopper key pasted into the Atlas Cloud provider
  -> accepted by validation

The Hopper provider has no base_url field: every Hopper configuration validates against and runs against https://api.withhopper.com/v1,
so a Hopper key cannot be routed to another host by a wrong or empty URL. Validation runs on Save Configuration; a rejected key is never persisted.
Atlas Cloud's GET /v1/models answers 200 to any key, so a Hopper key pasted there passes validation and fails at call time (pre-existing Atlas behaviour).
